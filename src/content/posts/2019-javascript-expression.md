2019 年我花了不少时间重新学习 JavaScript。之前也写过一些脚本，但更多是照着例子改。直到后来开始认真看变量、函数、对象、数组这些基础，才发现自己其实只是会用一点，并没有真的理解它。

![JavaScript 表达](/images/posts/personal-growth/2019-javascript-expression.jpg)

JavaScript 最吸引我的地方，是它很适合表达页面上的变化。按钮被点击，数据被更新，列表重新渲染，用户输入被检查，这些都可以用很直接的方式写出来。它不像一门离生活很远的语言，而是和网页上的每一个动作连在一起。

刚开始我经常被异步弄糊涂。代码明明写在前面，结果却不一定先发生。请求、回调、Promise，这些概念让我意识到，程序不是一条永远直线向下的路。它更像一组等待发生的事情，需要你安排好先后和关系。

学习 JavaScript 也让我慢慢重视命名。以前觉得变量名随便写，只要能跑就行。后来代码稍微长一点，就会发现糟糕的命名会让自己完全看不懂。一个清楚的名字，其实是在给未来的自己解释当下的想法。

那一年我写了很多小练习：待办事项、计时器、简单表单、图片切换。它们都不复杂，但每一个都让我更熟悉“状态”这件事。页面不是静止的，它会因为数据变化而变化。

现在再看，JavaScript 带给我的不只是语法能力，而是一种表达方式。它让我学会把用户动作、数据变化和页面反馈联系起来。技术学习很多时候就是这样，先是会写，后来才慢慢明白自己在表达什么。

## 从语法到模型

真正让我理解 JavaScript 的，是把页面想象成一组状态和事件。状态描述“现在是什么样”，事件描述“发生了什么”，函数则负责把两者连接起来。这个模型一旦建立，很多零散知识就能放到同一张图里。

比如待办事项并不只是数组操作，它包含新增、完成、删除、筛选和保存；计时器也不只是 `setInterval`，它还涉及开始、暂停、重置和边界状态。把这些动作写清楚以后，代码才不只是语法练习，而是在描述一个小系统。

## 我踩过的典型坑

最常见的坑是把变化藏得太深。一个变量在很多地方被修改，页面显示又依赖它，最后就很难判断问题从哪里来。后来我学会尽量让数据变化集中一点，让函数名字说明它会改变什么。

另一个坑是忽视异常路径。只处理“用户按正确顺序操作”的情况，项目看起来能跑，但一旦用户输入为空、网络失败、重复点击，问题就会出现。JavaScript 教会我的表达，不只是表达顺利流程，也要表达那些不顺利时应该如何回应。
