刚开始写代码的时候，其实没有想过以后要靠它做什么。那时更多是一种很单纯的好奇：为什么在一个黑色窗口里敲几行字，屏幕上就会出现另一个结果。这个过程看起来有点神奇，也有点不讲道理。

![第一行代码](/images/posts/personal-growth/2017-first-line-code.jpg)

我记得最早接触的是一些很基础的页面和脚本。照着教程写，文件名经常保存错，路径也经常找不到。一个分号、一个括号、一个大小写，都可能让我卡上半个晚上。那时候我并不懂什么工程化，也不知道什么设计模式，只知道报错了就一行一行看，实在看不出来就从头再敲一遍。

现在回头看，那段时间最重要的收获不是学会了某个语法，而是第一次体会到“问题可以被拆开”。一个看起来完全无法理解的错误，只要愿意慢慢找，总能找到线索。它可能在控制台，也可能在文件路径里，也可能只是自己少看了一行提示。

那时的学习效率并不高。很多概念今天看明白了，第二天又忘了。做出来的东西也很粗糙，页面排版歪歪扭扭，交互只能算勉强能用。但每一次刷新页面看到变化，都有一种很实在的满足感。

后来我才意识到，技术启蒙不一定来自宏大的目标，很多时候只是来自一次小小的成功：按钮真的被点到了，文字真的变色了，数据真的显示出来了。它们不起眼，却足够把一个人往前推一点。

2017 年对我来说，就是这样开始的。没有特别漂亮的开场，也没有清晰的路线图，只是在一台普通电脑前，笨拙地敲下第一行代码，然后慢慢知道，原来自己可以和机器讲一点点道理。
